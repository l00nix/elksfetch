# ELKSfetch 0.1

Initial native ELKSfetch release, prepared as a draft in the private repository.
Written in C for 8086-class ELKS systems; no Bash, Python or external runtime
assets are needed on the target.

## Included

- Small and wide ASCII logos, colour, monochrome and compact layouts.
- ELKS release, hostname, platform, user, uptime, kernel memory pools and TTY.
- Optional explicitly configured machine label.
- Live network state and IPv4, with netmask/gateway where supported by `ktcp`.
  A stopped stack shows `Network: disconnected`.
- Remote IA16 build script and candidate ELKS external-build/image-inclusion
  patch following the ELKSWeb integration approach.
- README, build instructions and genuine QEMU/HP 200LX screenshots.

## Installation

Download the `elksfetch` release asset and install it as `/bin/elksfetch` on
ELKS. On FAT, use the host image builder/mtools for the long filename, or name
an in-guest copy `elkfetch`. On MINIX, the full name works normally.
Run `elksfetch --version` to check for `elksfetch 0.1`.

The source archive contains the tagged source, documentation and integration
candidate. `SHA256SUMS` covers the downloadable executable, source archive
and screenshot assets. The executable is 10,928 bytes, built for i8086 using
IA16 GCC 6.3.0 and the prepared ELKS tree at
`e1469b64c5809c44d5c822eaeebd0e97d5996289`.

## Validation

- Six host renderer/CLI test groups and 13 network collector scenarios passed.
- This exact 0.1 executable passed ELKS/QEMU runtime checks: version output,
  system fields, advancing uptime, CLI errors, redirected output, FAT short
  filename, missing-device fallback, and networking start/stop with live
  IPv4/netmask/gateway values. The attached QEMU screenshot uses this binary.
- The preceding development build passed the physical HP 200LX DS smoke test
  and disconnected-network check over serial. Its ELXcap screenshot is included
  and labelled as a development-build capture. The 0.1 change is the version
  string; the retagged binary was revalidated in QEMU, not reinstalled on the HP.

## Current limits

“Connected (configured)” means the live stack has an IPv4 address; it does not
verify physical carrier or Internet access. Older `ktcp` versions fall back to
IPv4 only and can add about two seconds while the optional query times out.
The active-link fallback has host-fixture coverage but has not yet been tested
on the HP with networking enabled. PPC 512 hardware acceptance remains pending.

Kernel memory pools are not total physical RAM, and the platform string is not
CPU detection. DOSfetch is not implemented. The upstream integration patch has
not been submitted. The repository and this release remain private; this is an
unpublished draft.
